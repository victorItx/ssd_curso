# PresupuestosPro Constitution

## Core Principles

### I. Simplicidad ante todo
Ante dos soluciones, siempre elegimos la más simple. Esta es una versión 1 y no se debe añadir complejidad anticipada ni funciones “por si acaso”. El objetivo es entregar valor con claridad y rapidez.

### II. Idioma y mercado
Todo el producto se desarrolla en español de España. La moneda base es el euro. La experiencia de usuario, textos, avisos y mensajes deben ajustarse a ese idioma y contexto de mercado.

### III. Cero alcance fantasma
No se implementa ninguna funcionalidad que no esté escrita en la especificación. Si surge una idea nueva, se propone y se documenta; no se construye sin haber sido aprobada en la spec.

### IV. Verificable por una persona no técnica
Cada criterio de éxito debe poder comprobarse usando la app sin leer código. Si una funcionalidad no puede demostrarse desde la interfaz, no está lista para considerarse completada.

### V. Datos del usuario con respeto
Solo se pedirán los datos imprescindibles. No se introducirán claves, secretos ni información sensible en el código ni en archivos de configuración accesibles por defecto.

## Governance
La constitución guía todas las decisiones del producto. Si una idea, cambio o mejora entra en conflicto con estos principios, se rechaza o se re-encaja en la spec antes de implementarse.

Las decisiones de diseño deben mantenerse simples, claras y verificables. Cualquier cambio relevante debe revisarse frente a estos principios antes de cerrarse.
